Документ для обговорення з командою.

## 1. Що будуємо

**WickWorld** — український дитячий освітній портал для створення анімацій та ігор на базі [Wick Editor](https://github.com/Wicklets/wick-editor).

**Девіз:** Творити, вивчати, ділитись.

| Стовп | Опис |
|-------|------|
| Творити | Редактор Wick у браузері, проєкти зберігаються в хмарі |
| Вивчати | Уроки, лабораторії, покрокові завдання (пізніше) |
| Ділитись | Публічна галерея, ремікси (пізніше) |

**Цільова аудиторія:** діти 9–16 років, українська мова інтерфейсу.

**Поточний стан:** у репозиторії є статичний HTML-макет головної сторінки (`wickworld.html`). Бекенду, акаунтів і редактора ще немає.

## 2. Технічний стек

| Шар | Технологія | Навіщо |
|-----|------------|--------|
| Портал (UI + API) | Next.js (App Router) | Full-stack у одному репо: сторінки, API routes, SSR |
| База даних | Supabase (PostgreSQL) | Метадані проєктів, користувачі, RLS |
| Файли (.wick) | Supabase Storage | Хмарне збереження анімацій |
| Авторизація | Supabase Auth | Реєстрація / вхід учнів |
| Хостинг | Vercel (Hobby) | Безкоштовний старт, auto-deploy з GitHub |
| Редактор | Fork Wick Editor | Окремий репозиторій. Білд редактора деплоїмо самі на наш домен (`/editor`), а не iframe з wickeditor.com |

**Чому саме так:** без окремого API-сервера, безкоштовно на старті, швидкий MVP, зрозумілий шлях масштабування.

## 3. Архітектура: два репозиторії

- `balelkin/wickworld` — портал (Next.js + Supabase)
- `balelkin/wick-editor` — форк Wicklets/wick-editor + наш міст Save/Load

Офіційний репозиторій [Wicklets/wick-editor](https://github.com/Wicklets/wick-editor) залишається **upstream** — джерело оновлень. Ми не пушимо в їхній репо.

Форк **не підтягує оновлення автоматично**. Wicklets може пушити в `master` — наш продакшен від цього не зміниться, поки ми самі не оновимо форк і не задеплоїмо його знову. Так і треба: автозлив може зламати Save/Load. Про нові релізи можна дізнатися через Watch на GitHub (краще «Releases»).

### 3.1. Як працює редактор

Wick Editor — окремий Create React App (React 16). Його **не вбудовуємо в Next.js як npm-пакет** — це технічно несумісно.

Замість цього:

1. Збираємо форк Wick у статичний білд (`npm run build`).
2. Next.js віддає його з шляху `/editor/*`.
3. Сторінка порталу `/projects/[id]/edit` показує редактор у iframe на тому ж домені.
4. Звʼязок портал ↔ редактор — через `postMessage`, не через DOM.

### 3.2. Як працює збереження (ключове рішення)

**Не працює:** iframe з wickeditor.com і «перехопити кнопку Save». Браузер блокує доступ до чужого origin.

**Працює:** Wick уже передбачив платформний хук у `src/files/filehandler.js`. До завантаження редактора підміняємо `window.saveFileFromWick`: замість download на диск файл (Blob `.wick`) іде батьківському вікну → API Next.js → Supabase Storage.

Це офіційний патерн Wick (так зроблено для desktop). Ядро редактора не чіпаємо — лише один файл-міст.

### 3.3. Потік Save / Load

**Save**

1. Учень натискає Save.
2. Wick серіалізує проєкт у Blob (`.wick`).
3. `window.saveFileFromWick` → `postMessage` → батьківське вікно (Next.js).
4. `POST /api/projects/[id]/save` → Supabase Storage + оновлення Postgres.
5. Відповідь «ok» → Wick показує успіх учню.

**Load**

1. Next.js завантажує `.wick` зі Storage.
2. `postMessage` → iframe → існуючий API Wick (`importProjectAsWickFile`).
3. Редактор готовий до роботи.

**Правило безпеки:** Save в хмару дозволений лише після успішного Load. Інакше порожній проєкт може перезаписати збережену роботу.

Перші задачі розробки — fork Wick, міст Save/Load і перевірка циклу: відкрити → намалювати → зберегти → перезавантажити → малюнок на місці. Далі — кабінет і акаунти.

## 5. Roadmap

Три етапи. Інтеграція редактора входить у Етап 1, окремого «спайку без UI» немає.

### Етап 1 — MVP для уроків (орієнтовно 5–7 тижнів)

**Мета:** учень має акаунт, список проєктів, редактор з хмарним збереженням. Можна використовувати на уроці.

| # | Функція | Деталі |
|---|---------|--------|
| 1.1 | Fork Wick Editor | `balelkin/wick-editor` від Wicklets, upstream налаштовано, версія зафіксована |
| 1.2 | Міст Save/Load | Override `saveFileFromWick` + Load через postMessage |
| 1.3 | Перевірка циклу | Load → малювання → Save → reload → малюнок на місці |
| 1.4 | Next.js scaffold | App Router, TypeScript, клієнт Supabase |
| 1.5 | Auth | Email + пароль (Supabase Auth), мінімальна реєстрація |
| 1.6 | Проєкти | Створити / перейменувати / видалити / список «Мої проєкти» |
| 1.7 | Storage | `.wick` у бакет `projects/{userId}/{projectId}.wick` |
| 1.8 | Редактор на порталі | `/projects/[id]/edit` → iframe `/editor` |
| 1.9 | Ліміти | Макс. розмір файлу (напр. 25 MB), макс. проєктів на учня (напр. 20) |
| 1.10 | RLS | Учень бачить лише свої проєкти |
| 1.11 | Deploy | Vercel + Supabase, env vars |

**Не входить у Етап 1:** галерея, ремікс, уроки, кабінет вчителя, коментарі.

**Компроміс для уроків:** кнопка «Показати вчителю» — посилання лише для перегляду (без окремого кабінету вчителя).

### Етап 2 — Спільнота (орієнтовно 4–6 тижнів)

**Мета:** діти публікують роботи, дивляться чужі, роблять ремікси.

| # | Функція |
|---|---------|
| 2.1 | Публічна галерея (головна сторінка з макету) |
| 2.2 | Статус проєкту: private / public |
| 2.3 | Перегляд чужого проєкту (HTML-експорт або embed player) |
| 2.4 | Ремікс: копія `.wick` собі + посилання на автора оригіналу |
| 2.5 | Базова модерація: скарга / приховати проєкт |

### Етап 3 — Освіта (6+ тижнів)

**Мета:** структуроване навчання, гейміфікація, інструменти для вчителя.

| # | Функція |
|---|---------|
| 3.1 | Курси / уроки (контент + завдання) |
| 3.2 | Лабораторія (як у макеті) |
| 3.3 | Гейміфікація: бейджі, прогрес |
| 3.4 | Кабінет вчителя: клас, список учнів, перегляд робіт |
| 3.5 | Кабінет модератора |

## 6. Модель даних (MVP)

**profiles** (розширення Supabase Auth)

- `id` — uuid, PK, посилання на auth.users
- `display_name` — text
- `created_at` — timestamptz

**projects**

- `id` — uuid, PK
- `user_id` — uuid, FK → profiles
- `title` — text
- `storage_path` — text (`projects/{user_id}/{id}.wick`)
- `visibility` — private / public (за замовчуванням private)
- `remix_of` — uuid, nullable, FK → projects
- `created_at`, `updated_at` — timestamptz

**Storage bucket:** `projects`. Політика: власник шляху = `user_id` з JWT.

## 8. Ризики та мітигація

| Ризик | Ймовірність | Мітигація |
|-------|-------------|-----------|
| Wick оновлюється і ламає наш патч | Середня | Пін версії upstream; оновлення свідомо, не auto-merge |
| `.wick` файли великі (звук, картинки) | Висока | Ліміт розміру; превʼю = PNG, не повний HTML |
| GPL copyleft на весь портал | Низька | Редактор ізольований (iframe + postMessage) |
| Дитяча безпека / модерація | Висока (етап 2+) | Спочатку лише private; модерація перед публікацією |
| Autosave Wick vs хмара | Середня | MVP: явний Save; автозбереження в хмару — після стабільного циклу |
| Старий стек Wick (React 16, node-sass) | Середня | Не чіпаємо; білд з фіксованою версією Node |

## 9. Питання для обговорення з командою

1. **Auth для дітей:** email + пароль достатньо, чи потрібен вхід через Google / код від вчителя?
2. **«Показати вчителю»** — достатній компроміс для Етапу 1, чи одразу потрібен клас / група?
3. **Домен:** wickworld.com.ua чи піддомен на існуючому?
4. **Модерація (етап 2):** хто модерує — команда чи волонтери-вчителі?
5. **Контент уроків (етап 3):** хто пише — методисти, вчителі, чи спочатку 3–5 demo-уроків від нас?
